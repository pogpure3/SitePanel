# Журнал изменений

Формат основан на [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/),
версии — по [семантическому версионированию](https://semver.org/lang/ru/).

Даты указаны по локальному времени сервера разработки (Europe/Moscow).
`1.0.0` — состояние на момент первой публикации репозитория; в нём не было
ни одного из исправлений безопасности, поэтому первый релиз с тегом — `1.0.1`.

## [Unreleased]

  списка браузера; шрифт Manrope подключён по образцу API прокачки.
- В Mesh Portal добавлен выбор тёплой темы «Осень» (по умолчанию) и
  прежней тёмной темы; выбор сохраняется в браузере.
- На `panel_test` развернут Mesh Portal `prtl.evil-mesh.ru`. Он использует
  отдельную локальную учётную запись и открывает SitePanel, PQR и API прокачки
  по коротким одноразовым подписанным билетам. Прямой вход каждого проекта
  сохранён.

- Кнопки перехода из Mesh Portal используют токен CSRF, привязанный к сессии.
  Переход работает при браузерном `Origin: null`; чужой токен отклоняется.
- Приёмники билета в SitePanel, PQR и API прокачки теперь проверяют подпись,
  аудиторию, срок и одноразовость без зависимости от заголовка Origin браузера.

### Безопасность

- **Compose-файлы Docker-сайтов валидируются на опасные для хоста конструкции**
  (ревью). Раньше панель подменяла публикацию порта только у первого сервиса, а
  остальной compose выполняла как есть: второй сервис с `ports: 0.0.0.0:…`
  публиковался наружу в обход панели и файрвола, bind-маунт `/` или
  `/var/run/docker.sock`, `network_mode: host`, `privileged`, `pid: host` отдавали
  контейнеру хост целиком (панель работает с правами docker). Теперь при деплое и
  запуске файл разбирается js-yaml и отвергается (HTTP 400 с внятной ошибкой)
  при: `network_mode: host|container:*`, `privileged`, `pid/ipc: host`, `cap_add`,
  `devices`, external-сетях, `include`, внешнем `extends`, bind-источниках и
  `build.context` вне каталога сайта. Порты всех сервисов, кроме первого,
  сбрасываются override'ом (`ports: !reset []`). Docker-сайты целиком выключаются
  `PANEL_DOCKER_SITES=0`.
- **npm-скрипты docker-проектов больше не исполняются на хосте** (ревью).
  `npmInstall` гонялся до определения типа: docker-проект с `package.json`
  исполнял `postinstall`/`prepare` от имени панели, обходя изоляцию контейнера.
  Теперь для docker-проектов (в том числе в подкаталоге монорепо) установка на
  хосте пропускается — зависимости ставятся только в образе.
- **WebSocket-апгрейд чистит Authorization панели** (H-14 добит для WS): HTTP-путь
  удалял закэшированную браузером учётку панели перед проксированием, апгрейд —
  нет.
- **Заголовки безопасности применяются и к трафику сайтов** (H-13). Раньше
  `securityHeaders` стоял только на Express-приложении админки: сырые
  http/https-серверы прокси отдавали ответы сайтов и заглушки без
  `X-Content-Type-Options`, `X-Frame-Options`, `Referrer-Policy` — каждый
  размещённый сайт можно было встраивать в iframe (кликджекинг) и подвергать
  MIME-sniffing. Теперь все ответы публичного прокси получают `nosniff`,
  `X-Frame-Options: SAMEORIGIN`, `Referrer-Policy: no-referrer` и HSTS по HTTPS;
  заглушки (404/403/503) — ещё и CSP `default-src 'none'`, замыкающий вектор
  отражённого XSS из 1.0.2.
- **Учётные данные панели больше не уходят в приложения сайтов** (H-14).
  Браузер, закэшировавший Basic-пароль панели, отправлял его в `Authorization`
  каждому размещённому сайту — любой чужой код мог собрать пароль панели.
  Теперь заголовок, совпадающий с учёткой панели (проверка кэшируется, как во
  входе), удаляется перед проксированием; чужие `Authorization` — собственная
  Basic-авторизация сайта (например, MeshCentral) — проходят как есть.
  Подделанные клиентом `X-Forwarded-*` перед проксированием удаляются: http-proxy
  дописывал к ним, и поддельное `X-Forwarded-For: 9.9.9.9` оставалось первым.
  Заголовки собираются заново из реального сокета, `X-Forwarded-Host` — из
  проверенного имени хоста. То же на WebSocket-апгрейде.
- **`X-Forwarded-Proto` принимается только от доверенного источника** (H-07).
  Раньше любой клиент, попавший напрямую на HTTP-порт, заголовком
  `X-Forwarded-Proto: https` гасил редирект на HTTPS и включал HSTS. Схема
  учитывается только для loopback (nginx на той же машине) и адресов из
  `PANEL_TRUST_PROXY` (список через запятую заменяет умолчание; `*` — доверять
  всем).
- **Файловый менеджер не проводит симлинки наружу** (H-03, остаток). `safePath`
  проверял путь лексически: симлинк внутри каталога сайта на `.env` соседа или
  `/etc/passwd` можно было прочитать через `GET /file` и перезаписать через
  `PUT /file`. Добавлена проверка реального пути (`realpath`, с обходом к
  ближайшему существующему родителю для создаваемых файлов); симлинки внутри
  каталога продолжают работать.
- **ACME: параллельные выпуски больше не роняют друг друга** (H-04).
  Карта challenge-токенов ключуется `домен|токен`, и `finally` выпуска удаляет
  только свои токены — раньше завершение выпуска для сайта A стирало challenge
  сайта B, и тот падал по таймауту. Challenge отдаётся только на том домене,
  для которого выпускается сертификат (раньше — на любом `Host`). Продление
  идёт по одному сайту за тик, интервал — с джиттером.
- **ACME: выпуск под локом сайта и с предохранителями** (H-18). Ручной выпуск
  больше не накладывается на цикл продления того же сайта (два CSR в одни
  файлы); целевой каталог (staging/production) существующего сайта берётся из
  его записи, а не из глобальной настройки; повторный выпуск раньше чем через
  минуту отклоняется (расход лимита дубликатов Let's Encrypt).
- **`POST /ssl/issue` валидирует `domains`** через тот же `normalizeDomain`,
  что и привязку доменов (H-19): произвольные строки больше не попадают в
  сохраняемый `site.ssl.domains`, CSR и продление.
- **CSRF-защита усилена вторым барьером** (A-03): помимо `X-Requested-With`,
  кросс-сайтовые `Origin`/`Referer` и `Sec-Fetch-Site: cross-site` отклоняются.
- **Токен Telegram больше не покидает сервер** (A-02). `GET /api/settings`
  возвращает `telegramTokenSet` и подсказку с последними 4 символами вместо
  открытого токена в DOM; `PUT` меняет токен только новым значением (маска и
  пустота означают «оставить»), стирание — явным `telegramTokenReset`. Токен
  маскируется и в журналах ошибок Telegram. Поле в интерфейсе — парольное.
- **Пропажа `fullchain.pem` при живом `privkey.pem` больше не роняет панель**
  (H-17): `ensureDefaultCert` требует оба файла и перегенерирует пару.
- **Режимы файлов из архива маскируются до `0o755`** (H-20): архив больше не
  может привезти файл, исполняемый и записываемый для всех (0777); executable-бит
  владельца сохраняется.
- **WebSocket-апгрейд с чужим `Origin` разрушается** (H-21): браузерный
  кросс-сайтовый WS-запрос всегда несёт Origin чужого сайта. Отсутствие Origin
  (не-браузерный клиент) проходит.
- **Смена пароля пишется в журнал панели** (A-05) — с пользователем и адресом,
  без самого пароля.


- **`/healthz` для внешнего мониторинга панели** (7.4/I-06): без авторизации,
  отдаёт только факт живости и аптайм — без версий, путей и состава сайтов.

### Изменено

- **Пороги диска/памяти в оповещениях меняются современным контролом**:
  степпер (− значение +) вместо голого number-инпута со штатными стрелками и
  ползунок с заполненной дорожкой; кнопки, ввод и ползунок синхронизированы,
  значение клампится в 1–99. Имена полей формы не менялись.
- **Интерфейс админки переработан в стиле nginx-ui** (референс —
  demo.nginxui.com): боковое меню (Дашборд, Сайты, Терминал, Пользователи,
  Настройки) с активным пунктом-«пилюлей» и сворачиванием, шапка с хлебной
  крошкой и переключателем темы, карточки-панели. Список сайтов переведён с
  карточек на таблицу (статус, домены, память, обновлён, действия) с
  клиентским поиском. Все прежние URL (`#/`, `#/sites`, `#/sites/<id>`,
  `#/sites/<id>/files`, `#/settings`) работают, добавлены `#/terminal` и
  `#/users`; форма смены логина/пароля переехала из «Настроек» в
  «Пользователи». Устранена гонка отображения: устаревший ответ фонового
  опроса больше не перерисовывает страницу другого раздела. Истечение сессии
  уводит на страницу входа (см. «Страница авторизации»), а не показывает
  баннер «обновите страницу».
- **Телеметрия монитора больше не пишется в `db.json`** (M-02). Раньше каждые
  30 секунд `health`/`fails` каждого сайта вызывали полную перезапись реестра на
  диске — рост файла и износ носителя ради данных, не обязанных переживать
  рестарт. Теперь телеметрия живёт в памяти монитора (API отдаёт её как прежде),
  из `db.json` ключи выбрасываются при загрузке, тики монитора защищены от
  наслоения guard'ом, а период тика настраивается `PANEL_MONITOR_TICK_MS`
  (по умолчанию 30 с).
- **Миграция прав (`hardenDataDir`) выполняется один раз** (M-04). Раньше каждый
  старт панели обходил всё дерево `data/` — включая `node_modules` сайтов — и
  выставлял права заново. Теперь список путей фиксированный (`db.json`,
  `auth.json`, `state.json`, `sites/*` + `.env`/`config.json`, `certs/*/privkey.pem`,
  `acme/account-*.pem`), а факт выполнения фиксируется маркером
  `data/.permissions-hardened` с версией.
- **Статистика процессов кэшируется на 5 секунд** (M-07): `tasklist` на Windows и
  чтение `/proc` больше не выполняются на каждый запрос списка сайтов. Кэш ключуется
  по pid — после перезапуска сайта устаревший pid не возвращается.
- **Карточка диска при сбое показывает честное «н/д»** (M-05): метка времени
  обновляется только при успешном замере (при сбое повтор на следующем тике),
  ошибка читается в `diskError` snapshot'а, плавающий промис убран.
- **systemd-юнит в README**: `Restart=on-failure` вместо `always` с
  `RestartSec=5` и лимитами серии (`StartLimitIntervalSec=60`,
  `StartLimitBurst=5`) — иначе занятый порт (код выхода 1) давал вечный цикл
  рестартов (I-02). Требование Node поднято до `>=20` (M-06): `fs.statfs`
  появился только в 18.15, документация обещала весь 18-й.
- **Мелочи HTTP-слоя** (H-10): `TRACE` на публичном прокси отклоняется `405`
  (`OPTIONS` проходит к приложению — легитимный preflight); статические сайты
  отдают диагностический `X-Sitepanel-Site`, как и node-приложения; блокировка
  служебных путей перепроверена на закодированных вариантах (`%2e%2e`,
  двойное кодирование) — покрыто тестом.


- **Статика отдаёт `ETag`/`Last-Modified` и обрабатывает условные запросы**
  (H-08): неизменившиеся файлы отвечают 304 вместо полной перекачки. Текстовые
  типы больше килобайта сжимаются gzip (с `Vary: Accept-Encoding`).
- Новая переменная окружения `PANEL_TRUST_PROXY` — список доверенных
  фронт-прокси для `X-Forwarded-*` (см. «Безопасность»).
- `package-lock.json` синхронизирован с версией `1.0.2`.


- **Деплой собирает новую версию в staging ДО остановки сайта** (P-04, посильная
  часть blue/green). Распаковка, установка зависимостей и сборка идут, пока
  прежняя версия обслуживает трафик; окно 503 сократилось до «остановить →
  подменить → запустить», а ошибка клонирования/сборки больше вообще не касается
  работающего сайта (раньше сайт останавливался до клонирования). Полное
  переключение портов (настоящий blue/green) не реализовано.
- **Прямой запуск `node <файл>` вместо `npm start`** (P-09): если скрипт `start`
  — это просто `node <путь>`, панель исполняет его без npm-обёртки (минус два
  процесса и ~87 МБ RSS на сайт). Проверка уже была в коде — подтверждена чтением.
- **Токен Telegram не подставляется в DOM** (A-02): поле парольное и пустое,
  с подсказкой «сохранён (***XXXX)»; токен уходит на сервер только при вводе нового.

  - U-01: при 401 интерфейс больше не зацикливает `location.reload()` — таймеры

  - U-05: `.btn-icon` удалён, время в подсказках через общий помощник;
  - U-07: `.panel.span2` — исправлен селектор-потомок, панели «Логи»/«Опасная

### Добавлено

- **Реальный IP клиента до приложений за доверенным прокси** (`PANEL_FORWARD_CLIENT_IP=1`).
  По умолчанию панель отбрасывает клиентские `X-Forwarded-*` и собирает их заново
  из сокета (H-14), поэтому за nginx все размещённые сайты видели `127.0.0.1`, и
  IP-whitelist приложений не срабатывал. Новый флаг заставляет панель при
  соединении от доверенного форвардера (loopback или `PANEL_TRUST_PROXY`) взять
  последний хоп присланного `X-Forwarded-For` (его дописывает nginx — это реальный
  клиент), отбросить клиентский `x-real-ip` и передать этот адрес приложению как
  `X-Forwarded-For`/`X-Real-IP`. По умолчанию поведение прежнее: подделанные
  заголовки по-прежнему отбрасываются.
- **Docker-сайты: деплой проектов через Dockerfile и docker-compose.yml** (zip и Git).
  Новый тип сайта `docker`: панель определяет проект по `Dockerfile` или
  `docker-compose.yml|compose.yaml|compose.yml|docker-compose.yaml` (приоритетнее
  package.json), собирает образ при деплое (`PANEL_DOCKER_BUILD_TIMEOUT_MIN`) и
  пересоздаёт контейнеры с префиксом `sitepanel-<id>`. Публикация — только на
  `127.0.0.1:<выделенный порт>:<порт из EXPOSE/ports, иначе 3000>` (для compose
  панель генерирует override с `!override` для первого сервиса); наружу — только
  реверс-прокси панели, включая WebSocket. Жизненный цикл: контейнер переживает
  рестарт панели (`unless-stopped` у Dockerfile-проектов), статус синхронизируется
  health-check'ом и `docker inspect`, откат/восстановление пересобирают образ,
  удаление сайта чистит контейнеры, образы и тома проекта. Порт контейнера
  редактируется в карточке сайта (`PATCH /api/sites/:id`, поле `containerPort`).
  Дополнительно: Docker-файлы в подкаталоге `deploy/` с build-контекстом на корень
  репозитория — поддерживаются (сборка с явным `-f`); контейнеры compose-проектов
  отслеживаются по label проекта (пользовательский `container_name` не мешает);

  прочие volume-данные не теряются); хвостовые комментарии в строках `ports`
  compose-файла учитываются при детекте порта.

### Безопасность

- **Реестр сайтов больше не теряется от одного испорченного байта.** `load()`
  ловил ошибку разбора **голым** `catch { /* первый запуск */ }`: обрезанный
  `db.json` давал `sites: []`, и первая же мутация через `flush()`
  **перезаписывала единственную копию** пустым состоянием — реестр из двух
  сайтов уничтожался, каталоги на диске оставались «ничьими». Теперь панель
  уходит в аварийный режим (`recoveryMode`, `src/store.js:39,143,168`),
  повреждённый файл откладывается, предыдущее поколение читается из
  `db.json.bak` (`src/store.js:156`), записи валидируются
  (`validateSite`, `src/store.js:58`), а `flush()` в аварийном режиме не пишет
  ничего и отвечает `5xx` вместо тихой перезаписи.
- **Заглушки больше не отдают введённый путь и `Host` как разметку.** Доказанный
  сквозной XSS: `GET /%3Cimg%20src%3Dx%20onerror%3Dalert(1)%3E` — панель
  декодировала путь и вставляла его в заглушку 404 без экранирования и без CSP.
  Добавлено экранирование (`esc()`, `src/httpserver.js:61`) и корректный
  `hostOf` (`src/httpserver.js:75`), который **отбрасывает имя хоста целиком**,
  если оно не подходит под `/^[a-z0-9._-]+$/`, и правильно разбирает
  IPv6-литерал (`[::1]:8443` → `::1`). Редирект на HTTPS больше не опирается на
  подконтрольный `Host`.
- **Вход в админку перестал быть усилителем отказа в обслуживании.**
  `crypto.scryptSync` вызывался **на каждый** запрос к админке в том же
  event loop, что обслуживает реверс-прокси сайтов: замер на стенде показывал
  **52.2 мс** на вызов и рост отклика сайта с `0.000890 с` до `0.320018 с`
  (**в 360 раз**) при 8 авторизованных запросах. `scrypt` стал асинхронным,
  добавлены ограничение неудачных попыток и блокировка по IP
  (`PANEL_LOGIN_MAX_FAILS`=10, `PANEL_LOGIN_WINDOW_MS`=5 мин,
  `PANEL_LOGIN_LOCKOUT_MS`=15 мин, потолок одновременных проверок 2, задержка
  500 мс — `src/auth.js:27-34`), а успешные проверки кэшируются
  (`PANEL_AUTH_CACHE_MS`=60000, до 512 записей, ключ — `sha256(user \\0 password)`,
  сам пароль в памяти не хранится). Итог: ухудшение отклика сайта под теми же
  8 запросами — **медиана ×1.08, p95 ×1.25** при пороге «не более 2×».
- **Оболочка админ-панели больше не слушает все интерфейсы.** `adminHost` по
  умолчанию `127.0.0.1` (`src/config.js:26`), порт 3100 доступен только с самого
  сервера (снаружи — через nginx); при необходимости вернуть прежнее поведение
  задаётся `PANEL_ADMIN_HOST=0.0.0.0`. Каталоги данных создаются с режимом
  `0o700` (`src/config.js:81`), права `data/` сравниваются **по битам**, а не по
  величине.
- **Кривая `Authorization` больше не даёт `500`** — отдаётся `401`; добавлен
  общий JSON error-middleware, а `/api/*` выведен из SPA-fallback (неизвестный
  маршрут API отвечает JSON-404, а не HTML-страницей интерфейса).
- **Подкаталог репозитория не может вывести за пределы распаковки.**
  `validateSubdir` допускал `..` (`../../sites/<id>`) и молча срезал ведущий
  слэш у абсолютного пути (`/etc` → `etc`). Теперь запрещены `..`, `.` и
  абсолютные пути, а выход за пределы каталога проверяется через
  `path.relative` (`assertInside`, `src/sites/manager.js:774`) — дважды: до
  переноса каталога и после.
- **`git clone` не может висеть вечно и не спрашивает пароль.**
  `GIT_TERMINAL_PROMPT=0`, `GIT_ASKPASS=echo`,
  `GIT_SSH_COMMAND='ssh -o BatchMode=yes -o StrictHostKeyChecking=accept-new'`,
  таймаут `PANEL_GIT_TIMEOUT_MIN` (по умолчанию 5 мин) с убийством **группы**
  процессов (`killTree`). *Этап 2:* таймаут не срабатывал — `spawn` не имел
  `detached`, поэтому `killTree` бил по группе **панели**, а не `git`'а, и потомок
  `git-remote-https` переживал сигнал. Промис `gitClone` не завершался никогда, а
  вместе с ним вечно держалась блокировка сайта. Добавлены `detached` **и**
  независимое от события `close` завершение промиса (`GIT_CLOSE_GRACE_MS` = 5000)
  — см. «Исправлено».
- **Панель не запускается вторым экземпляром** (`SP-08`). Замок
  `data/sitepanel.lock` (`src/instancelock.js`): атомарная запись `tmp`+`rename`
  (`0600`), проверка живого pid (`kill(pid, 0)`, `EPERM` считается «занят»),
  протухший замок перезаписывается. Берётся **до** создания каталогов данных.
  Проверено на живом боевом стенде: второй старт отклоняется сообщением
  «Уже запущен другой экземпляр панели (pid …, процесс уже работает)».
- **Zip-бомба с подделанным заголовком больше не съедает память** (`P-15`).
  Счётчик распакованных байтов не защищал: `adm-zip` разжимает запись целиком
  внутри `entry.getData()`, а при заявленном размере `0` вообще снимает
  ограничение (`maxOutputLength` не передаётся). Замер на архиве 203 962 байта из
  200 МБ нулей с подделанным `uncompressed size = 0`: **рост RSS +368 МБ** на
  прежнем коде. Теперь распаковка идёт через собственную `inflateBounded` с
  `zlib.inflateRawSync(..., { maxOutputLength })`, сверкой фактической длины с
  заявленной и собственной проверкой `crc32` — **рост RSS 0 МБ**.
- **Отказ в обслуживании через лимиты окружения закрыт** (`P-16`).
  `PANEL_MAX_UNCOMPRESSED_MB=0` (и отрицательные значения) не «отключал» защиту,
  а ломал её: `int()` возвращал `0`, сравнение `totalBytes > maxBytes` становилось
  заведомо ложным. Все числовые пределы читаются через `posInt(v, dflt, min, max)`
  (`src/config.js:125`); то же относится к `config.json`.
- **Зависший апстрим больше не держит сокет** (`H-06`). `createProxyServer`
  получил `proxyTimeout: PANEL_PROXY_TIMEOUT_MS` (60 с). Опция `timeout` **убрана
  намеренно**: она ставит таймаут на сокет КЛИЕНТА и вместо страницы `502` рвёт
  соединение (`ECONNRESET`) — проверено пробой из четырёх вариантов.
- **Распаковка архива через файловый менеджер требует подтверждения** (`P-31`):
  `extract=1` без `confirm=1` → `400`, файл не распакован и не потерян.

### Исправлено

- **Обновление панели больше не отрезает доступ к самой панели.** Релиз 1.0.1
  считал хеш пароля по параметрам `scrypt` по умолчанию (`N=16384`) и **не
  записывал их в `auth.json`** — там только `user`, `salt`, `hash`. Параметры
  были подняты до `N=32768`, и хеш из прежнего файла с ними совпасть не мог:
  верный пароль перестал бы подходить, то есть обновление ломало бы вход на
  каждом существующем стенде. Теперь параметры хранятся рядом с хешем, файл без
  `params` читается по прежним значениям (`LEGACY_SCRYPT_OPTS`,
  `src/auth.js:206-234`), а после **успешного** входа хеш пересчитывается и файл
  получает `params` (`src/auth.js:331-348`). Недоверенные `params` из файла
  проверяются по границам — иначе подменённый `N=1048576` превращал каждый вход
  в четырёхкратный `scrypt`.
- **Битый `auth.json` больше не обнуляет пароль.** Файл откладывается в сторону
  (`<auth.json>.corrupt-<timestamp>`), панель отказывается работать
  (`failHard`, `src/auth.js:167-185`) вместо генерации новой учётной записи —
  раньше один испорченный байт молча уносил доступ навсегда.
- **Пароль с двоеточием не усекается:** заголовок `Authorization` разбирается по
  **первому** `:`.
- **`adm-zip` обновлён `^0.5.16` → `^0.6.1`** — закрывает 4 advisory
  (`GHSA-j5f4-cc29-5x44` SUID/SGID из недоверенного архива,
  `GHSA-p634-w6r4-rjp2` дубли записей, `GHSA-c6fg-446q-cg94` обход
  `maxOutputLength` в `getDataAsync`, `GHSA-8238-w5pm-2374` DoS в async DEFLATE).
  В `package-lock.json` версия была рассинхронизирована с `package.json` —
  приведены в соответствие.
- **Самоподписанный сертификат выпускался с подписью SHA-1.** У `selfsigned`
  значение по умолчанию для `algorithm` — `'sha1'`, и панель этот параметр не
  передавала. Современные клиенты (Chrome, Firefox, curl на OpenSSL 3) отвергают
  такой сертификат **на уровне рукопожатия**, ещё до проверки цепочки: обращение к
  HTTPS-порту панели падало с `TLS alert handshake failure`, хотя `openssl s_client`
  соединение устанавливал. Теперь явно задан `sha256`
  (`src/ssl/certs.js:27-32`, применяется в `ensureDefaultCert` и `issueSelfSigned`).
- **HTTPS-сервер обрывал соединение, если клиент не прислал SNI.** У
  `https.createServer` был только `SNICallback` и не было `key`/`cert` по умолчанию;
  при обращении по IP (SNI не отправляется) `SNICallback` не вызывается вовсе, и
  сервер отдавал `TLS alert handshake failure` (alert 40) вместо сертификата
  по умолчанию. Добавлены `...certs.defaultCertFiles()` (`src/httpserver.js:194`).
- **При распаковке zip терялся executable-бит, а защита от symlink'ов не работала.**
  `entryMode()` читала `entry.header.attributes`, но у `adm-zip` свойство называется
  `attr` (геттер на central header) — `attributes` в библиотеке нет вовсе. Функция
  **всегда** возвращала `null`: скрипты вида `scripts/start.sh` из архива приезжали
  неисполняемыми, а ветка обработки symlink'ов в `extractZip` была мёртвым кодом —
  то есть небезопасные ссылки не отсекались как задумано. Исправлено на чтение
  `entry.attr` (`src/sites/manager.js:421`).
- **`validateGitUrl` отклонял легитимные адреса GitLab/self-hosted** с вложенными
  группами (`group/sub/repo`): регулярка знала только форму `owner/repo`. Заодно
  ни один сегмент пути не может начинаться с `-` — иначе `git` принял бы его за
  флаг (`--upload-pack=…`).
- **Блокировки сайтов больше не «залипают».** Очередь освобождается в `finally`
  (`src/sites/lock.js:38`), повторный вход в блокировку отклоняется, `removeSite`
  и `_rollback` не удерживают блокировку и откатываются через атомарный
  `swapWithBackup`.
- **Остановка панели стала предсказуемой:** `shutdown` идемпотентен
  (`src/index.js:21,117,121`), повторный сигнал завершает процесс немедленно,
  дочерние процессы получают `SIGKILL` через 3 с, выход — через 5 с; ошибка
  `store.flush()` не глотается, а попадает в лог.
- Исправлено предупреждение `PANEL_NO_AUTH` — обращалось к несуществующему
  `config.host` вместо `config.adminHost`.

Дефекты, найденные регрессионными тестами **этапа 2** (каждый воспроизведён до
правки):

- **Смерть панели посреди деплоя оставляла сайт без каталога.** Деплой делал
  `rename(dir → dir.backup)`, а затем `rename(staging → dir)`; `SIGKILL` в этом
  окне оставлял сайт без рабочего каталога навсегда. Теперь перед каждой
  перестановкой пишется маркер (`data/tmp/deploy-<id>.json`), а при старте
  `deploymark.reconcile` восстанавливает каталог из `.backup`. Проверено 20
  прогонами с `SIGKILL`: **потеряно каталогов 0/20**.
- **Сайт без открытого порта считался живым** (`P-03`). `_start` объявлял успех
  по факту запуска процесса, не проверяя, что приложение реально заняло порт;
  деплой «удавался», а сайт отвечал `502`. Добавлена `waitListening`
  (`PANEL_APP_LISTEN_WAIT_MS`, 10 с) — без порта запуск считается провалом.
- **Синхронный сбой `spawn` отдавал `500` вместо `crashed`** (`P-27`). Если `cwd`
  сайта — не каталог (или недоступен), `spawn` бросает **синхронно**;
  исключение вылетало из `_start` и превращалось в `500 {"error":"spawn ENOTDIR"}`,
  а сайт навсегда оставался в `starting`. Вызов обёрнут в `try/catch`: в лог
  попадает причина, статус становится `crashed`, уходит алерт.
- **`_stop` сообщал об успехе, если порт остался занят** (`P-19`). Результат
  `ensurePortFreed` отбрасывался, поэтому следующий запуск падал с `EADDRINUSE`
  без внятной причины. Теперь при неудаче возвращается `{ ok: false }` с
  перечислением удерживающих порт pid'ов. При этом `ensurePortFreed` убивает
  **только свои** процессы (`P-18`): чужой процесс на порту не трогается, в лог
  идёт предупреждение «это не процесс сайта — сигнал не отправлен».
- **Карточка подхваченного сироты отвечала `500`** (`Cannot read properties of
  null (reading 'pid')`): `monitor.statsFor` обращался к `proc.child.pid`, а у
  внешнего процесса `child === null`.
- **Монитор мог затереть статус живого сайта** (`P-26`, `M-01`). `boot()`
  вызывался **после** `monitor.start()`, и первый тик через 5 с записывал
  `crashed` сайту, который панель ещё не подняла. Порядок исправлен, переходы
  статуса идут через `setStatusIf` (меняет только при ожидаемом текущем).
- **Подпроцессы деплоя переживали остановку панели** (`SP-05`): `npm install`
  размещаемого сайта продолжал работать после `SIGTERM` панели. Добавлен реестр
  живых подпроцессов (`activeCommands`, `killActiveCommands`), гасимый в
  `shutdown`.
- **Логи сайтов читались в память целиком** (`P-01`, `P-02`, `P-23`): запись была
  синхронной (блокировала event loop), а `GET /logs` читал весь файл. Запись
  стала асинхронной (`MAX_PENDING_BYTES` = 4 МБ), чтение — только хвоста
  (`logTailMaxBytes`), появилась ротация на N поколений (`logGenerations`).
- **Порт внутреннего сайта выделялся без проверки занятости в ОС** (`T-13`):
  `allocatePort` смотрел только на реестр и мог выдать порт, занятый посторонним
  процессом. Теперь порт проверяется пробой `listen` и `connect`.

Первый релиз с тегом. Закрывает утечку секретов через реверс-прокси и

### Безопасность

- **Статика больше не раздаёт служебные и секретные пути.** Запросы к dot-файлам
  и каталогам (`.env`, `.git/**`, `.htaccess`) и к `node_modules` возвращают 404,
  даже если файлы лежат в каталоге сайта. Раньше `.env` с секретами отдавался
  через реверс-прокси открыто, с `Cache-Control: public, max-age=3600`.
- **Заголовки безопасности** на ответах админ-панели: `Content-Security-Policy`
  (без `unsafe-inline` для скриптов), `X-Frame-Options: DENY`,
  `X-Content-Type-Options: nosniff`, `Referrer-Policy: no-referrer`,
  `Permissions-Policy`; HSTS включается, когда панель доступна по HTTPS,
  в том числе за прокси с `X-Forwarded-Proto: https`.
- **Защита от CSRF.** Мутирующие запросы к API требуют заголовок
  `X-Requested-With: XMLHttpRequest`: сторонняя страница не сможет выполнить
  действие от имени залогиненного администратора (Basic-авторизация
  подставляется браузером автоматически).
- **Права на файлы с секретами ограничены владельцем.** Приватные TLS-ключи
  (`privkey.pem` — `0600`, каталог сайта в `certs/` — `0700`), ключ аккаунта
  Let's Encrypt (`account-*.pem` — `0600`), `.env` размещаемых сайтов,
  `db.json` (в нём могут быть git-токены) и `auth.json` — `0600`.
  Раньше всё это писалось с `0644`, то есть было читаемо любому пользователю
  машины, включая код размещённых сайтов.
- Ключ аккаунта ACME, созданный прежними версиями, ужимается при старте панели
  (разовая миграция `hardenDataDir`).
- Заглушки ответов (404/403/503) отдаются с `Cache-Control: no-store`, чтобы
  временный сбой не «прилипал» в кэше посредников.

### Исправлено

- **Автоперезапуск падающего сайта зацикливался.** Счётчик попыток сбрасывался
  по факту «процесс прожил 1.5 с», поэтому падение позже этого окна давало
  бесконечный цикл «перезапуск №1 через 1 с». Теперь серия сбрасывается только
  после реально стабильной работы (`PANEL_RESTART_STABLE_SEC`, по умолчанию 60 с),
  причём с повторной проверкой живости процесса — иначе таймер сбрасывал счётчик
  уже мёртвому процессу. Наблюдалось на реальной установке: падение каждые 64 с
  при лимите 5 попыток и полном отсутствии эскалации.
- После исчерпания лимита автоперезапуск останавливается, сайт помечается как
  «цикл перезапуска», включается остывание (`PANEL_RESTART_COOLDOWN_MIN`, 10 мин).
  Ручной запуск сбрасывает серию падений.
- **Определение диска на Windows не работало.** Использовался `df`, которого там
  нет, поэтому карточка «Хранилище» в дашборде всегда оставалась пустой.
  Основной путь теперь — `fs.statfs` (Node ≥ 18.15), `df` оставлен как резерв
  для старых систем и нестандартных ФС.
- **`npm test` не работал на Node 20 и мог запускать чужие тесты.** Glob
  `tests/**/*.test.js` не поддерживается Node 20, а bare `node --test`
  рекурсивно сканирует дерево и подхватывал тесты размещённых сайтов из
  `data/sites/*/tests/`. Добавлен `tests/run.js` — собирает `tests/*.test.js`
  сам, без внешних зависимостей и без шелла.
- `nextBackoffDelay` возвращал `NaN` при некорректном входе, что превратило бы
  паузу перед перезапуском в мгновенный цикл.
- Процесс, осиротевший после `taskkill /T` (обёртка `npm`/`cmd` рвёт дерево),
  продолжал держать порт, и следующий запуск падал с `EADDRINUSE`. Панель
  находит слушателя порта и завершает его принудительно.

### Добавлено

- **Автоматический откат при неудачном деплое.** Если новая версия не
  запускается, панель возвращает предыдущую из бэкапа и сообщает об этом
  в интерфейсе. Раньше сайт просто оставался лежать, хотя бэкап уже был.
- **Мьютекс на сайт** (`src/sites/lock.js`): деплой, откат, запуск, остановка,
  перезапуск и удаление одного сайта выполняются строго по очереди, разные
  сайты — параллельно. Убирает гонки за каталог и порт при одновременных запросах.
- **Установка зависимостей по lock-файлу** (`src/sites/deployfiles.js`):
  `npm ci`, `pnpm/yarn/bun install --frozen-lockfile`, с откатом на обычный
  `install` при рассинхроне lock-файла. Раньше всегда выполнялся `npm install`.
- Таймауты на установку зависимостей и сборку (`PANEL_INSTALL_TIMEOUT_MIN`,
  10 мин), с принудительным завершением дерева процессов.
- **Защита от zip-бомб** при распаковке: ограничения на суммарный несжатый
  размер (`PANEL_MAX_UNCOMPRESSED_MB`) и число файлов (`PANEL_MAX_ZIP_ENTRIES`).
- Сохранение прав из архива (executable-бит) и безопасная обработка symlink'ов:
  абсолютные ссылки и выход за каталог сайта отбрасываются с записью в лог.
- Индикатор цикла перезапуска в списке сайтов и на странице сайта: видно номер
  попытки, а после исчерпания лимита — что автоперезапуск остановлен.
- Поля диагностики перезапусков в API: `restartAttempts`, `restartCount`,
  `lastCrashAt`, `crashLoop`.
- `tests/run.js` и 46 тестов, включая проверки прав на файлы с секретами.
