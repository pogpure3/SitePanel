# SitePanel — панель управления сайтами на Node.js

Однопроцессная панель для хостинга нескольких сайтов на одном сервере: загрузка сайтов zip-архивом,
привязка доменов, SSL-сертификаты Let's Encrypt, мониторинг состояния, запуск / остановка / обновление сайтов.

## Возможности

- **Загрузка сайтов** — zip-архив через веб-интерфейс. Тип определяется автоматически:
  - есть `package.json` со скриптом `start` → **Node.js-приложение** (запускается как дочерний процесс, приложение обязано слушать `process.env.PORT`);
  - иначе → **статический сайт** (раздаётся напрямую из каталога).
- **Домены** — привязка любого числа доменов к сайту, поддержка wildcard (`*.example.com`); маршрутизация реверс-прокси по заголовку `Host`. Подсказка по DNS-настройке в интерфейсе.
- **SSL**:
  - **Let's Encrypt** по HTTP-01 challenge (автоматический выпуск и продление за 30 дней до истечения, есть staging-режим для отладки);
  - **Self-signed** сертификаты для локальной разработки;
  - динамический SNI — сертификаты подставляются по имени домена, HTTP автоматически редиректит на HTTPS после выпуска сертификата.
- **Управление** — запуск, остановка, перезапуск; автоперезапуск при падении (по умолчанию 5 попыток
  с нарастающим интервалом 1с → 4с → 16с → 64с → 256с); после исчерпания лимита автоперезапуск
  останавливается и сайт помечается как «цикл перезапуска» — серия падений сбрасывается только после
  стабильной работы (по умолчанию 60с) или при ручном запуске, поэтому падающий сайт не может
  перезапускаться бесконечно; автозапуск при старте панели; обновление новой версией zip
  с сохранением бэкапа и откатом одной кнопкой.
- **Мониторинг** — health-check каждые 30 секунд с историей проверок, память процесса, PID, аптайм; просмотр логов сайта (stdout+stderr) с автообновлением.
- **Админ-панель** — веб-интерфейс на русском, страница входа с сессией в HttpOnly-cookie (плюс HTTP Basic для API и скриптов), тёмная/светлая темы, веб-терминал, смена логина/пароля.

## Быстрый старт

```bash
npm install
npm start
```

При первом запуске панель напечатает **сгенерированный пароль администратора** в консоль
и сохранит учётные данные в `data/auth.json`.

По умолчанию: админ-панель — `http://localhost:3000`, реверс-прокси — порты **80** (HTTP) и **443** (HTTPS).
Порты 80/443 требуют прав администратора (Windows) или root / `CAP_NET_BIND_SERVICE` (Linux).
Для разработки задайте порты переменными окружения:

```bash
PANEL_HTTP_PORT=8080 PANEL_HTTPS_PORT=8443 PANEL_ADMIN_PORT=3000 npm start
```

Все переменные окружения: `PANEL_ADMIN_PORT`, `PANEL_HTTP_PORT`, `PANEL_HTTPS_PORT`,
`PANEL_DATA_DIR`, `PANEL_LE_EMAIL`, `PANEL_LE_STAGING`, `PANEL_LE_RENEW_DAYS`, `PANEL_UPLOAD_MAX_MB`,
`PANEL_INTERNAL_PORT_FROM` (внутренние порты node-приложений, по умолчанию с 10000),
`PANEL_RESTART_MAX_ATTEMPTS` (5), `PANEL_RESTART_STABLE_SEC` (60), `PANEL_RESTART_COOLDOWN_MIN` (10),
`PANEL_INSTALL_TIMEOUT_MIN` (10), `PANEL_MAX_UNCOMPRESSED_MB` (2048), `PANEL_MAX_ZIP_ENTRIES` (50000).

## Тесты

```bash
npm test        # полный набор: реальные панели на свободных портах, data/ не трогается
npm run lint    # eslint (минимальные правила: реальные дефекты, не стиль)
```

Тесты проверяют: заголовки безопасности, защиту от CSRF, недоступность `.env`/`.git`/`node_modules`
через прокси, поведение бэкоффа при падении сайта, авто-откат при неудачном деплое, сериализацию
операций по сайту, устойчивость деплоя к SIGKILL, шифрование/персистентность состояния и другое.

Браузерный прогон интерфейса (`tests/ui-browser.test.js`) требует Playwright — без него файл
скипается, набор остаётся зелёным:

```bash
npm i -D playwright && npx playwright install chromium
```

CI (`.github/workflows/ci.yml`) прогоняет `node --check`, eslint и полный набор на Node 20/22/24.

## Обслуживание стенда

`scripts/backup-sitepanel.sh` — бэкап `db.json`/`auth.json`/`state.json`/сертификатов
в `/root/sitepanel-backups/<ts>/` с ротацией; ставить в cron (пример — в шапке скрипта).
`scripts/harden-old-stand.sh` — усиление sshd/UFW/fail2ban/swap (НЕ применялся, требует
согласия и открытой второй ssh-сессии). `scripts/probe-external-db.sh` — диагностика
доступности внешней БД со стенда.

## Требования к сайтам

**Node.js-приложение** должно слушать порт из переменной окружения `PORT`:

```js
const port = process.env.PORT || 3000;
app.listen(port, '127.0.0.1');
```

Панель запускает `npm start` в каталоге сайта. Установка зависимостей выполняется
автоматически при деплое, менеджер пакетов определяется по lock-файлу:

| Файл в репозитории | Команда |
|---|---|
| `package-lock.json`, `npm-shrinkwrap.json` | `npm ci` (при рассинхроне lock-файла — `npm install`) |
| `pnpm-lock.yaml` | `pnpm install --frozen-lockfile` |
| `yarn.lock` | `yarn install --frozen-lockfile` |
| `bun.lock(b)` | `bun install --frozen-lockfile` |
| нет lock-файла | `npm install` |

Если в `package.json` есть скрипт `build`, он выполняется после установки.
Установка и сборка ограничены по времени (`PANEL_INSTALL_TIMEOUT_MIN`, по умолчанию 10 минут) —
зависший процесс не блокирует деплой навсегда.

Переменные окружения, доступные приложению: `PORT`, `HOST`, `SITE_ID`, `NODE_ENV=production`, `SITEPANEL=1`.

**Статический сайт** — просто файлы в архиве; корневой `index.html` служит главной страницей.
Если в архиве одна корневая папка, её содержимое автоматически поднимается на уровень выше.

> **Что не раздаётся через прокси:** dot-файлы и каталоги (`.env`, `.git/**`, `.htaccess`)
> и `node_modules` — запрос к ним возвращает 404, даже если файлы лежат в каталоге сайта.
> Хранить секреты внутри каталога статики всё равно не стоит; для Node-приложений
> надёжнее переменные окружения.

## Надёжность деплоя

- **Автоматический откат.** Если новая версия не запускается, панель возвращает
  предыдущую из бэкапа и сообщает об этом в интерфейсе. Без бэкапа (первый деплой)
  сайт остаётся в статусе «упал» — откатывать нечего.
- **Операции по сайту сериализуются.** Деплой, откат, запуск/остановка, перезапуск
  и удаление одного сайта выполняются строго по очереди, разные сайты — параллельно.
  Одновременные запросы не могут породить два процесса на один порт.
- **Архивы распаковываются безопасно.** Отсекаются zip-slip пути, `__MACOSX`, `.git`,
  опасные symlink'и; ограничен суммарный размер (`PANEL_MAX_UNCOMPRESSED_MB`) и число
  файлов (`PANEL_MAX_ZIP_ENTRIES`). Executable-бит из архива сохраняется (Linux/macOS).
- **Порты освобождаются принудительно.** `taskkill /T` не всегда достаёт до node,
  запущенного через `npm`/`cmd`: осиротевший процесс держит порт и следующий запуск
  падает с `EADDRINUSE`. Панель находит слушателя порта и завершает его.

## SSL Let's Encrypt: что нужно

1. Домен привязан к сайту в панели (без wildcard — wildcard требует DNS-01 и не поддерживается).
2. **A-запись домена указывает на IP этого сервера**.
3. **Порт 80 доступен из интернета** — панель сама отвечает на challenge `/.well-known/acme-challenge/*`.

Выпуск занимает до минуты; сертификаты продлеваются автоматически (проверка 4 раза в сутки).
Staging-режим включается в «Настройках» — используйте его для отладки, чтобы не упереться в лимиты LE.

## Запуск в production

### Linux (рекомендуется)

```bash
# Дать node права на привилегированные порты без root:
sudo setcap 'cap_net_bind_service=+ep' $(readlink -f $(which node))
```

Пример systemd-юнита `/etc/systemd/system/sitepanel.service`:

```ini
[Unit]
Description=SitePanel
After=network.target

[Service]
Type=simple
User=www-data
WorkingDirectory=/opt/sitepanel
ExecStart=/usr/bin/node src/index.js
# on-failure, а не always: выход с кодом 1 — это «порт занят другим
# экземпляром», и вечный рестарт каждые 5 секунд только забивал журнал.
Restart=on-failure
RestartSec=5
# Лимит серии рестартов: 5 попыток за минуту, дальше пауза до ручного разбора.
StartLimitIntervalSec=60
StartLimitBurst=5
Environment=NODE_ENV=production
Environment=PANEL_LE_EMAIL=admin@example.com
# Необязательно: лимиты автоперезапуска и таймаут установки зависимостей
# Environment=PANEL_RESTART_MAX_ATTEMPTS=5
# Environment=PANEL_INSTALL_TIMEOUT_MIN=10

[Install]
WantedBy=multi-user.target
```

При занятом порту панель печатает в журнал одно внятное сообщение
(«Порт … уже занят другим процессом — остановите прежний экземпляр панели»)
и завершается с кодом 1 — systemd с лимитами выше не зациклится.

### Windows

Запускать от имени администратора (порты 80/443), открыть порты в файрволе.
Для автозапуска — служба через `nssm` или задача Планировщика задач.

## Каталог данных (`data/`)

| Путь              | Содержимое                                        |
|-------------------|---------------------------------------------------|
| `db.json`         | Состояние: сайты, домены, SSL, настройки          |
| `db.json.bak`     | Предыдущее поколение `db.json` (для восстановления) |
| `auth.json`       | Логин и scrypt-хэш пароля админа                  |
| `state.json`      | Защёлки алертов (переживают рестарт панели)       |
| `sitepanel.lock`  | Замок единственного экземпляра                    |
| `sites/<id>/`     | Файлы сайтов; рядом `<id>.backup` — прошлый деплой |
| `certs/<id>/`     | `privkey.pem`, `fullchain.pem`                    |
| `logs/<id>.log`   | stdout/stderr сайтов (ротация)                    |
| `acme/`           | Ключи аккаунтов Let's Encrypt                     |

## Доступ к панели

Вход в интерфейс — через страницу `/login` (логин и пароль хранятся в `data/auth.json`,
хэш scrypt). Успешный вход выдаёт сессию в HttpOnly-cookie `sp_session`:

- TTL сессии — скользящий, по умолчанию 24 часа (`PANEL_SESSION_TTL_H`); активная
  работа продлевает сессию, рестарт панели сбрасывает все сессии;
- смена логина/пароля гасит все активные сессии;
- неудачные попытки ограничены: 10 за 5 минут с одного адреса — блокировка на 15 минут
  (`PANEL_LOGIN_MAX_FAILS`, `PANEL_LOGIN_WINDOW_MS`, `PANEL_LOGIN_LOCKOUT_MS`);
  счётчики общие для формы входа и HTTP Basic;
- «Выйти» (кнопка в шапке) гасит сессию на сервере.

HTTP Basic при этом продолжает работать — для API, `curl` и скриптов. Браузерная
навигация без сессии/пароля уводится на `/login?next=...`; API отвечает `401` JSON.

## REST API

Все эндпоинты требуют HTTP Basic-аутентификацию (браузерная форма входа выдаёт сессию в HttpOnly-cookie — см. раздел «Доступ к панели»); мутирующие запросы дополнительно требуют заголовок `X-Requested-With: XMLHttpRequest`.

| Метод | Путь | Описание |
|---|---|---|
| GET    | `/api/sites` | Список сайтов со статусами, health, статистикой |
| POST   | `/api/sites` | Создать: multipart `file` (zip), `name`, `autoStart` |
| GET    | `/api/sites/:id` | Сайт + история health-проверок |
| PATCH  | `/api/sites/:id` | Переименовать, `autoStart` |
| DELETE | `/api/sites/:id` | Удалить сайт, файлы и сертификаты |
| POST   | `/api/sites/:id/start\|stop\|restart` | Управление |
| POST   | `/api/sites/:id/update` | Обновление: multipart `file` (zip) |
| POST   | `/api/sites/:id/rollback` | Откат к предыдущей версии |
| GET    | `/api/sites/:id/logs?lines=200` | Хвост лога |
| GET    | `/api/sites/:id/health` | История health-проверок |
| POST   | `/api/sites/:id/domains` | Привязать домен `{"domain": "..."}` |
| DELETE | `/api/sites/:id/domains/:domain` | Отвязать домен |
| POST   | `/api/sites/:id/ssl/issue` | Выпуск LE `{"domains":[], "email":"", "staging":bool}` |
| POST   | `/api/sites/:id/ssl/selfsigned` | Self-signed сертификат |
| POST   | `/api/sites/:id/ssl/disable` | Отключить SSL |
| GET/PUT| `/api/settings` | Настройки LE |
| POST   | `/api/password` | Смена логина/пароля |
| GET    | `/api/system` | Информация о сервере |

## Ограничения и заметки по безопасности

- Админ-панель слушает HTTP без TLS — для доступа из интернета ограничьте порт файрволом,
  либо проксируйте через отдельный домен с сертификатом.
- Мутирующие запросы к API требуют заголовок `X-Requested-With: XMLHttpRequest` (защита от CSRF):
  без него сторонняя страница не сможет выполнить действие от имени залогиненного администратора.
  Если встраиваете панель в свой фронтенд — не забудьте этот заголовок.
- `X-Forwarded-Proto` (схема за реверс-прокси, влияет на редирект HTTPS и HSTS) принимается
  только от loopback или адресов из `PANEL_TRUST_PROXY` (список через запятую; `*` — доверять всем).
- Ответы админки отдают `Content-Security-Policy`, `X-Frame-Options: DENY`,
  `Referrer-Policy: no-referrer`, `X-Content-Type-Options: nosniff`; HSTS включается,
  когда панель доступна по HTTPS (в том числе за прокси с доверенным `X-Forwarded-Proto: https`).
  Ответы сайтов и заглушки прокси получают `nosniff`, `X-Frame-Options: SAMEORIGIN`,
  `Referrer-Policy: no-referrer` и HSTS по HTTPS; заглушки — ещё и CSP.
- Учётные данные панели не передаются приложениям сайтов: если `Authorization`
  совпадает с учёткой панели, из запроса к сайту он удаляется; чужие `Authorization`
  (собственная Basic-авторизация сайта) проходят как есть. Подделанные клиентом
  `X-Forwarded-*` перед проксированием удаляются и собираются заново.
- Загруженный код исполняется от имени пользователя панели — запускайте панель под
  непривилегированным пользователем, если хостите чужой код.
- Разные сайты не изолированы друг от друга (общая ОС и сеть). При хостинге чужих приложений
  рассмотрите изоляцию (контейнеры, отдельные пользователи).
- Логи хранятся открытым текстом; `data/` не должна быть доступна извне (она и не раздаётся прокси).

## Ротация ключей и секретов

- **Пароль панели** — `POST /api/password` (или форма «Настройки»). Событие пишется
  в журнал панели. Экстренный сброс при потере доступа: остановите панель, удалите
  `data/auth.json` — при старте панель сгенерирует новый пароль и напечатает его
  в журнале (stdout/journald).
- **Токен Telegram-бота** хранится только на сервере и не отдаётся интерфейсу;
  сменить — в настройках панели, стереть — там же (чекбокс «Удалить сохранённый токен»).
  При компрометации токена отзовите его через @BotFather (`/revoke`) и впишите новый.
- **Git-токены** хранятся в `data/db.json` (файл `0600`). При компрометации отзовите
  токен у провайдера (GitHub/GitLab) и выпустите новый, затем обновите его в карточке
  сайта при следующем деплое из Git.
- **Приватные ключи TLS** лежат в `data/certs/<id>/privkey.pem` (`0600`) и в
  `data/acme/account-*.pem` (`0600`, ключ аккаунта Let's Encrypt). Компрометация ключа
  аккаунта ACME — повод отозвать сертификаты и перевыпустить их (в LE ключ аккаунта
  можно заменить запросом newAccount с новым ключом).
- Бэкапы `data/` наследуют чувствительность этих файлов: храните их с теми же правами
  (`0600`) или шифруйте.
